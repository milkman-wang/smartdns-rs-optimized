# C 与新旧 Rust 性能对比，2026-09-12

本次功能适配存在明确的基础查询吞吐回退：新版无界面相较上一版下降约 10%–12%；启用 WebUI 后，相较新版无界面再下降约 7%–14%。三轮都出现同方向的差距，新旧 Rust 对应组的吞吐范围没有重叠。当前不应把这一轮功能适配称为性能优化。

C Release48.4 在热缓存、冷查询和 CPU 效率上领先新版 Rust；上一版 Rust 的静态规则吞吐高于 C，但使用更多服务 CPU。家用低负载下，四个版本的缓存命中 P99 中位数分别为 0.199、0.334、0.377、0.399 ms，绝对差距远小于饱和压测中的延迟差距。

## 产物和环境

- 路由器：小米 BE10000，QWRT 25.12.2 / R26.8.8，Linux 5.4.213，四核 AArch64。保持原来的 `ondemand` 调频，频点 936–2208 MHz。
- C 对照为[官方 Release48.4 的 AArch64 二进制](https://github.com/pymumu/smartdns/releases/tag/Release48.4)，运行时版本 `1.2026.08.05-0921`，5,301,472 字节。
- 上一版 Rust 是从当前路由器 `/usr/sbin/smartdns` 复制出的同一二进制，对应 `003a939` 的查询修复版，构建时间 `2026-09-11 12:00:51 UTC`，11,056,400 字节。
- 新版使用本次已暂存的功能适配代码，尚未提交。无界面版构建时间 `16:07:05 UTC`，11,753,392 字节；WebUI 版为 `16:08:28 UTC`，11,924,296 字节。
- 三个 Rust 产物均使用 Rust 1.96.0、`aarch64-unknown-linux-musl`、`openwrt` 功能、`opt-level=3`、单 codegen unit 和 thin LTO，WebUI 版额外启用 `webui`。这是实际交付产物比较；C 官方包的编译选项并未人为改成 Rust 的选项，文件大小也不代表纯语言开销。

## 测量方法

测试在独立网络命名空间中进行，只启用 loopback。客户端在 CPU 0，待测服务在 CPU 1–2，固定上游在 CPU 3。三个 Rust 版本均设置 `num-workers 2`；C 使用自身线程模型，启动后 6 个线程，同样受两个核心的 CPU affinity 限制。Rust 启动后为 3 个线程。正式 DNS 继续运行，未替换程序或配置。

所有版本用相同的 [Rust 基准工具](router_dnsbench.rs)，服务监听 5300，上游监听 5301，返回固定 `192.0.2.1`、TTL 3600。配置关闭测速、双栈选择、预取、过期缓存、缓存持久化和查询审计，缓存容量为 4096。WebUI 版启用页面服务及查询历史记录，本组测试期间没有浏览器的 HTTP 轮询。

每次启动后等 1 秒，再以并发 1 预热 1 秒。热缓存使用 256 个域名；冷查询使用 65,536 个域名，超过缓存容量，除最初少量预热命中外均需回源；静态规则使用 `address /bench/192.0.2.1`。这三类以最多 32 个未完成查询测量 5 秒。低负载单独以固定 100 QPS、最多 4 个未完成查询测量 10 秒。

每组测量 3 轮，轮间交错四个产物的顺序。下表为逐轮中位数，P95/P99 也是每轮百分位数的中位数，没有把三轮样本混合成总体百分位数。完整样本及环境见 [JSON 原始数据](c-rust-20260912.json)。

准备阶段修复了固定上游处理 EDNS 的问题：C 会附加 OPT，原工具错误地把 OPT 放在答案前。修正为只保留问题区后再生成答案，并通过两项报文单元测试及实际 C 查询。修复前的失败预热不纳入本报告；48 轮正式测量全部使用修正后的同一个工具。

## 复现

将四个产物及编译后的 `router_dnsbench` 放入测试目录，分别命名为 `smartdns-c`、`smartdns-previous`、`smartdns-headless`、`smartdns-webui`、`dnsbench`。使用 [运行脚本](run_c_rust_comparison.sh)：

```sh
ip netns add smartdns-perf-20260912
ip netns exec smartdns-perf-20260912 ip link set lo up
ip netns exec smartdns-perf-20260912 \
  env PERF_DIR=/tmp/smartdns-perf-20260912 \
  sh /tmp/smartdns-perf-20260912/run_c_rust_comparison.sh
# 脚本结束后收集 results.jsonl、配置和日志，再删除测试命名空间。
ip netns delete smartdns-perf-20260912
```

## 结果边界

这是同机 loopback 的相对性能比较，服务被限制在两个核心；QPS 不是整机或外部客户端的绝对容量。正式路由业务和调频仍可能产生波动，因此保留各轮原始数据及范围。

冷查询的固定上游没有公网 RTT；结果不能直接换算成网页加载速度。100 QPS 的延迟只覆盖有效缓存命中。未在这轮比较完整屏蔽规则、真实缓存文件、负缓存收益、集中预取、测速、加密协议或 WebUI 页面轮询，不能把本报告的小配置 RSS 当作实际部署内存。

新增功能的性能回退已经测得，但本轮没有做 CPU profiling，不能把无界面版的下降全部归因于某个统计计数器或缓存改动。WebUI 对照则包含查询历史记录这一明确的行为差异。
