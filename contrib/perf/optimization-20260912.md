# Rust 功能适配后的性能优化，2026-09-12

保留本轮新增功能后，无界面版热缓存吞吐提升 **16.2%**、冷查询提升 **12.0%**；WebUI 版分别提升 **15.8%** 和 **21.3%**。无界面版热缓存比上一版高 7.4%，冷查询基本恢复到上一版水平（中位数差 -0.6%）；静态规则仍低 6.8%。

无界面版热缓存吞吐与 C Release48.4 基本相当，但使用更多 CPU；C 的冷查询吞吐仍约为无界面版的 2.7 倍。这是实现层面的改进，不能据此得出 Rust 全面快于 C 的结论。

## 改动与定位依据

先在路由器上用 Linux `perf_event_open` 对带符号的优化前二进制采样，软件 CPU 时钟 499 Hz，每个场景 15 秒。热缓存取得 10,074 个用户态样本，冷查询取得 10,018 个，丢失样本均为 0。采样程序和带帧指针的产物只用于定位；下表吞吐数据来自正常 release 产物。

热缓存约 34% 的用户态样本落在复制、内存分配和释放相关函数中。固定域名解析占约 4.9% 的含子调用样本；冷查询的缓存内存估算占约 4.7%。中间件的含子调用占比包含后续整条查询链，不能全部归为该中间件自身开销。

据此进行了以下调整：

- DDR 的固定域名只解析一次；没有启用 DDR 的普通查询不再构造无用响应，保留 `resolver.arpa` 的本地应答。
- 根据实际配置决定是否加入 ipset/nftset 中间件，覆盖域名、监听器、客户端和规则组中的集合配置。
- 缓存内存占用在创建条目时计算并保存，更新、淘汰和过期时复用；准备条目放在缓存锁外。未修改的上游响应复用收到的报文长度，结构修改后重新估算。缓存容量和内存预算继续生效。
- 缓存插入和内部原始消息转换使用已有所有权，减少完整 DNS 响应的复制。
- UDP 接收缓冲区复用，查询任务直接发送回包，减少向接收循环传递回包的队列和唤醒。
- WebUI 保留每次查询记录，改为读取页面数据时格式化字符串，并在序列化前释放历史记录锁；保持既有 JSON 字段及失败状态文本。
- 没有注册扩展时直接跳过空注册表的锁操作；统计和已注册的扩展回调仍然执行。

功能回归还发现了此前客户端选项的合并顺序问题：监听器的 ipset 覆盖了客户端指定的 ipset。现在客户端显式选项优先，未指定的设置及请求来源等元数据继续继承；规则组仍遵循配置加载时的继承规则。相应单元测试和路由器真实集合写入已通过。

## 方法与产物

设备仍为小米 BE10000，QWRT 25.12.2 / R26.8.8，Linux 5.4.213，四核 AArch64。保持 `ondemand` 调频。客户端使用 CPU 0，服务使用 CPU 1–2，固定上游使用 CPU 3。Rust 均设为 2 个工作线程，C 使用自身线程模型，同样限制在 CPU 1–2。

C 对照为官方 Release48.4。上一版 Rust 是当前生产二进制的副本，构建时间 `2026-09-11 12:00:51 UTC`。优化前是本轮功能适配产物，分别构建于 `16:07:05`、`16:08:28 UTC`。最终优化版分别构建于 `18:00:07`、`18:01:37 UTC`；准确的完整版本字符串保存在 JSON 的环境字段。

Rust 均使用 Rust 1.96.0、`aarch64-unknown-linux-musl`、`openwrt` 功能、`opt-level=3`、thin LTO、单 codegen unit；界面版另加 `webui`。没有通过关闭原有功能获得这些收益。

六个版本采用同一套配置和负载，各运行三轮并轮换顺序。热缓存为 256 个域名、4096 条容量；冷查询为 65,536 个域名；静态查询使用 address 规则。每次预热 1 秒，吞吐测量 5 秒、并发窗口 32；低负载单独运行 10 秒、固定 100 QPS。固定上游返回 `192.0.2.1`、TTL 3600。

本组比较关闭测速、双栈选择、预取、过期缓存、持久化及审计，以隔离基础查询路径；所有版本均相同。WebUI 版开启查询历史，主表测试期间没有浏览器轮询。数据为逐轮中位数，P99 也是逐轮 P99 的中位数，未合并样本。完整数据见 [optimization-20260912.json](optimization-20260912.json)。

复现时，将对应产物放入测试目录，分别命名为 `smartdns-c`、`smartdns-previous`、`smartdns-before`、`smartdns-before-webui`、`smartdns-headless`、`smartdns-webui`，并提供同版本的 Rust `dnsbench`。在已启用 loopback 的独立网络命名空间中执行：

```sh
ip netns exec smartdns-opt-20260912 \
  env PERF_DIR=/tmp/smartdns-opt-20260912 \
  VARIANTS='c previous before before-webui headless webui' \
  sh /tmp/smartdns-opt-20260912/run_c_rust_comparison.sh
```

[运行脚本](run_c_rust_comparison.sh)保持默认四版本用法，并支持这次六版本对照。

## 验证与边界

- 最终完整测试：337 项通过，1 项忽略；Windows 和 Linux AArch64 Clippy 通过，格式检查通过。
- 新增覆盖缓存内存计量的替换和过期、收到报文长度的失效规则、所有集合配置来源、客户端选项优先级、IPv4/IPv6 多客户端并发 UDP 回包以及 WebUI 输出格式。
- 路由器上 10 次 IPv4/IPv6、UDP/TCP 查询通过；域名、监听器、客户端的七个 IPv4/IPv6 测试集合均验证了实际成员。停止上游后，缓存仍能应答并重新写入集合。
- 当前固件不支持 nftables 集合，正向 nftset 写入的实机验证限制仍然存在；本轮验证了 ipset。
- 两个 ARM64 IPK 测试包中的可执行文件均与被测最终二进制逐字节一致。

这是隔离的 loopback 小配置基准，不代表公网冷查询 RTT、完整规则集的内存或整机极限容量。C 在冷查询及每次查询 CPU 成本上仍有明显优势，上一版 Rust 的静态规则吞吐也仍高于最终版。没有把此次收益解释为 Rust 语言天然快于 C。

正式服务未替换，测试实例及测试集合在验证后清理。

另外，以界面默认的每 5 秒刷新一次的频率读取快照，同时运行固定 100 QPS 查询 15 秒：1,500 次响应全部正确，P99 为 0.449 ms，服务 CPU 为 1.7%。这是一次交互负载验证，不与主表的三轮统计混合。最终快照包含 1,000 条正确历史、256 条缓存，活动查询数为 0。
