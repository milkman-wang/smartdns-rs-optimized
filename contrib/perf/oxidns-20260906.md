# BE10000：SmartDNS-rs 与 OxiDNS，2026-09-06

## 版本与范围

SmartDNS-rs 为 [本轮已部署的优化版本](router-20260906.md)。OxiDNS 为上游发布的 [v1.5.2 full，aarch64-unknown-linux-musl](https://github.com/svenshi/oxidns/releases/tag/v1.5.2)，直接运行官方二进制。本轮未替换路由器正式 DNS 服务。

OxiDNS 的 [官方性能报告](https://oxidns.org/benchmarks/) 使用 Intel N100 和 OxiDNS 1.5.1，其中 SmartDNS 是 C 版 Release48.2，不能与本项目在 BE10000 的 QPS 相除。下面使用同机新测数据。

## 方法

- 同一 BE10000、相同 governor 和 CPU 分配：负载发生器及固定上游在 CPU 0，DNS 服务在 CPU 1–3。
- 使用独立网络命名空间 `smartdns-oxi-20260906`；生产 DNS 和正常路由业务继续运行。
- 两者均使用 4,096 条缓存、UDP 监听 5300、本地固定上游 5301；无测速、持久化、预取和管理界面。
- 普通 A 查询，上游回答 `192.0.2.1`、TTL 3600。客户端校验响应 ID、名称和答案。
- 每次启动后并发 1 预热 1 秒，再以并发 32 测量 5 秒，每组 3 轮。统计逐轮中位数。
- 热缓存使用 256 个域名；计时前暂停固定上游进程，计时后恢复。零错误和超时确认测量期无需上游回答。
- 最终冷缓存使用 1,000,000 个域名，每轮完成数小于域名数，保证计时区间不循环；固定上游持续运行。使用命名空间内的 iptables 计数器核对实际回源数。每轮仅清理测试命名空间内目标为 127.0.0.1:5301 的 UDP 连接。

复现脚本见 [run_oxidns_comparison.sh](run_oxidns_comparison.sh)，原始结果见 [oxidns-20260906.json](oxidns-20260906.json)。脚本的 OxiDNS 配置依据该版本的 [官方缓存基准配置](https://github.com/svenshi/oxidns/blob/v1.5.2/benchmarks/configs/common/oxidns/02-cache-hotpath.yaml)，将缓存容量、端口及工作线程与本测试统一。

## 热缓存结果

| 三轮中位数 | SmartDNS-rs，2 线程 | OxiDNS，2 线程 | SmartDNS-rs，4 线程 | OxiDNS，4 线程 |
|---|---:|---:|---:|---:|
| QPS | 52,012.2 | 76,568.5 | 37,250.9 | 66,894.4 |
| P95 | 0.966 ms | 0.603 ms | 1.405 ms | 0.865 ms |
| P99 | 1.157 ms | 0.805 ms | 2.168 ms | 1.238 ms |
| CPU，100%=一核 | 176.4% | 174.6% | 132.2% | 174.2% |
| RSS | 7,032 KiB | 7,964 KiB | 7,096 KiB | 8,004 KiB |
| 错误、超时 | 0 | 0 | 0 | 0 |

两者在本机本负载下都是 2 线程更快。比较各自的 2 线程结果，OxiDNS 的热缓存吞吐高 47.2%，P99 低约 30.4%；小配置 RSS 多约 0.91 MiB。这里使用本次同时段的 SmartDNS-rs 数据，不与上一轮凌晨的 55,081 QPS 混算。4 线程配置的波动较大，保留全部样本。

## 唯一域名冷查询：速度与内存取舍

| 三个有效样本中位数，均为 2 线程 | SmartDNS-rs | OxiDNS |
|---|---:|---:|
| QPS | 13,573.7 | 25,105.8 |
| P95 | 3.131 ms | 2.294 ms |
| P99 | 4.173 ms | 3.257 ms |
| CPU，100%=一核 | 182.5% | 161.0% |
| 测量结束 RSS | 11,452 KiB | 186,408 KiB |
| 已完成样本的错误、超时 | 0 | 0 |

每个有效样本的上游计数都严格等于完成查询数减 255，差值来自预热时已缓存的域名。其余查询均回源，没有在域名池内循环。OxiDNS 的中位数高 85.0%，但同样配置 `size: 4096` 时，本轮结束 RSS 为 143,984–199,500 KiB，约 141–195 MiB；其缓存容量并非逐次插入后的硬上限。不能把这个结果描述成“同等内存下快 85%”，也没有测出持续负载的内存上限。

OxiDNS 第二次唯一域名尝试没有输出有效计时样本；最初循环没有保存该次退出码和预热日志，原因未确认，因此没有把它计为零错误的成功轮次。单独补测一次成功，原始数据明确标为 `oxidns-unique-2-retry`。有效 OxiDNS 样本为 20,207–27,189 QPS，波动较明显，不足以承诺持续容量。

### 排除的冷缓存口径

最初沿用 65,536 个域名循环、配置容量 4,096 的测试，OxiDNS 测得约 5.3 万 QPS、RSS 约 100 MiB。其 [缓存源码](https://github.com/svenshi/oxidns/blob/v1.5.2/src/plugin/executor/cache/mod.rs) 使用周期和限额淘汰，配置容量并非严格即时边界。

增加回源计数后的诊断轮完成 230,244 次查询，实际仅回源 67,277 次，约 70.8% 没有回源。因此这组初始数据仅保留为 `excluded_churn_not_cold`，不用于冷查询性能结论；上表改用不循环域名的实测结果。

## 复现命令

使用上一份报告中编译的 `dnsbench`，准备两个二进制和本报告的脚本，然后在路由器上运行：

```sh
D=/tmp/smartdns-perf
N=smartdns-oxi
ip netns add "$N"
ip netns exec "$N" ip link set lo up
ip netns exec "$N" iptables -t mangle -A OUTPUT -p udp -d 127.0.0.1 --dport 5301
ip netns exec "$N" taskset 1 "$D/dnsbench" server 5301 &
echo $! > "$D/compare-upstream.pid"
ip netns exec "$N" env PERF_DIR="$D" sh "$D/run_oxidns_comparison.sh" \
  smartdns "$D/smartdns" 2 cache smartdns-w2
ip netns exec "$N" env PERF_DIR="$D" sh "$D/run_oxidns_comparison.sh" \
  oxidns "$D/oxidns" 2 cache oxidns-w2
# 将 cache 改为 cold 测量不循环域名的冷查询。
# 每轮 cold 后只清理该测试命名空间中的连接：
ip netns exec "$N" conntrack -D -p udp --dst 127.0.0.1 --dport 5301
kill "$(cat "$D/compare-upstream.pid")"
ip netns delete "$N"
```

## 进一步优化的判断

本轮额外编译并测试了缩短 `DnsCache::get` 持锁范围的候选版本：在释放缓存锁之后执行 CNAME 名称检查和 TTL 修改。该候选未部署到正式服务。

候选的 2 线程中位数为 50,415.9 QPS（比本次当前版低 3.1%），4 线程为 37,657.8 QPS（高 1.1%）。候选轮次在两引擎对照轮次之后，不把小幅差异视为确定因果；它没有测出值得保留的收益，因此撤回这一候选，保留上一轮已验证的实现。

更进一步的方向是减少 UDP 请求经过的任务、通道和响应复制，以及评估缓存并发结构；仅从源码形态不能确定各自对差距的贡献，需要单独采样和验证，不能据此承诺追平 OxiDNS。

源码依据：本项目的 UDP 入口、`DnsHandle` 通道和应用批次处理分别位于 `src/server/udp.rs`、`src/server/mod.rs`、`src/app.rs`；缓存使用互斥锁保护 LRU。OxiDNS 1.5.2 的 [缓存实现](https://github.com/svenshi/oxidns/blob/v1.5.2/src/infra/cache/ttl.rs) 使用 DashMap，缓存值通过 Arc 共享。这是结构差异，尚未证明是本轮性能差距的主要原因。

本轮没有保留新的 Rust 运行逻辑改动。原有 11 个相关单元测试结果仍对应待提交实现，比较脚本通过 ShellCheck，所有有效计时样本的答案校验通过。测试完成后清理了 OxiDNS、模拟上游和网络命名空间；生产二进制与测试前一致。再次执行 160 次 A/AAAA 和 12 次 UDP/TCP 功能检查通过，本地域名 UDP 为 0.55–1.26 ms。没有运行全仓库测试或 OpenWrt SDK 打包。

## 结果边界

这是简单 A 查询的闭环饱和负载，包含路由器上的客户端开销。冷缓存是本地固定上游，不能推导公网 DoH/DoT 延迟。没有将完整分流、测速、广告规则、持久化和 IPv6 策略迁移到 OxiDNS，也没有验证两者功能完全等价。RSS 是小配置的驻留内存，不是当前正式配置的内存。
