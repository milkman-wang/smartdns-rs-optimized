# 超过 C 版吞吐的性能优化，2026-09-12

同一路由器、相同配置和 CPU 资源下，无界面版与 WebUI 版的热缓存、冷查询、静态规则吞吐均稳定超过 C SmartDNS Release48.4。两版在这三个场景中的最低吞吐均高于 C 的最高吞吐；每次查询的 CPU 成本和固定低负载延迟均比本轮优化前降低。

以下为三轮中位数。这里的“超过”指这三类吞吐，不表示所有指标都优于 C。

|---|---:|---:|---:|---:|---:|
| C Release48.4 | 56,933 | 41,336 | 62,580 | 0.190 | 6.84 |

| 优化前 WebUI | 52,068 | 14,065 | 62,212 | 0.312 | 13.74 |
| 最终无界面 | 102,693 | 45,259 | 108,840 | 0.225 | 15.07 |

## 保留的改动

- 请求任务直接执行中间件并回包，删除中心队列和批量分发；保留重载、活动查询统计、后台并发限制和空闲停止预取。
- UDP 上游复用独占的连接套接字和缓冲区，完成查询后回收；超时、取消、大小写验证失败时丢弃。保留随机 ID、来源、问题、大小写、EDNS、代理、设备和标记选项。
- 单问题 UDP 查询直接编码问题和 EDNS，借用参数，减少完整请求对象的构造和传递。响应解析留在同步函数中，减少异步状态中的大对象复制。
- 响应和缓存共享不可变消息，修改内容时才复制；回包编码共享内容并替换客户端响应头，保留段计数、扩展错误码和截断标志。
- 缓存短暂的纯内存操作使用同步互斥锁；访问统计保留 SystemTime，读取时再转换日期。内存预算、LRU、TTL、负缓存、预取和持久化继续生效。
- 无异步操作的本地区域提供器改为同步调用；删除重复 Future 装箱、单上游选择队列和旧缓存写入实现；借用配置，并跳过空的引导 DNS 缓存查找。
- WebUI 的常见 IP 答案保存在内联小数组中，其他答案保留类型；仍记录每次查询，在读取快照时格式化，保持历史上限和 JSON 字段。
- 仅在 64 位 musl 目标使用 mimalloc，其他平台保持原分配器。单独对照确认该调整显著降低了 musl 分配开销。

检查中还修复了不支持的 DNS opcode 会触发 panic，以及响应头丢失上游 TC 截断标志的问题。公开协议、负响应、IPv4/IPv6、并发、取消、重载及缓存的回归覆盖继续通过。

定位使用路由器上的 perf_event_open 采样和本地固定版本源码。早期复制和 musl 分配占用最高；后续同时采样内核与用户态，确认剩余差距主要在用户态。提前轮询 UDP 的尝试增加了饱和冷查询 P99，单工作线程降低了吞吐，均未保留。WebUI 共享整份响应的中间方案增加了热缓存内存占用，也已被紧凑答案替换。

## 方法与验证

设备为小米 BE10000，QWRT 25.12.2，Linux 5.4.213，四核 AArch64，保持 ondemand 调频。客户端固定在 CPU 0，服务固定在 CPU 1–2，模拟上游固定在 CPU 3。Rust 使用两个工作线程，C 保持自身线程模型并受同样 CPU 亲和性限制。版本、构建时间、内核及 CPU 信息保存在数据文件的 environment 字段。

“优化前”是上一轮性能优化的最终两版，已逐字节确认基线副本一致。Rust 使用 1.96.0、aarch64-unknown-linux-musl、openwrt、opt-level=3、thin LTO、单 codegen unit；WebUI 版另加 webui。最终性能数据来自正常 release 产物，没有混入采样专用产物。

全部版本缓存容量为 4096。热缓存使用 256 个域名，冷查询使用 65,536 个域名，静态规则为 `address /bench/192.0.2.1`。预热 1 秒，吞吐测量 5 秒、并发窗口 32；低负载为固定 100 QPS、10 秒。上游返回 192.0.2.1、TTL 3600。测速、双栈选择、预取、过期缓存、持久化和审计均关闭。WebUI 版启用 1000 条查询历史，主表测量期间没有页面轮询。各轮轮换版本顺序。

复现时，在已启用 loopback 的隔离网络命名空间中，把五个产物命名为 `smartdns-c`、`smartdns-before`、`smartdns-before-webui`、`smartdns-final`、`smartdns-final-webui`，并提供同版 Rust `dnsbench`：

```sh
ip netns exec smartdns-perf env PERF_DIR=/tmp/smartdns-perf \
  VARIANTS='c before before-webui final final-webui' ROUNDS=3 \
  SCENARIOS='cold cache static latency' \
  sh /tmp/smartdns-perf/run_c_rust_comparison.sh
```

- 最终完整测试：349 项通过，0 项失败，1 项忽略；Windows 和 AArch64 musl Clippy、格式检查通过。
- 两版均在路由器隔离实例上验证 IPv4/IPv6、UDP/TCP、域名/监听器/客户端 ipset，以及停止上游后的缓存应答和集合重新插入。
- 当前固件未启用 nftables 集合支持，正向 nftset 写入仍无法在该固件实测；未修改固件。
- 两个 ARM64 IPK 的可执行文件均与最终被测二进制逐字节相同，权限为 0755；未安装到正式服务。

这组结果适用于隔离的基础查询路径，不代表公网 RTT、完整规则集或所有指标都超过 C。套接字池和分配器增加了少量常驻内存，表中保留了实际 RSS。正式服务未替换，测试实例和集合已清理。

完整逐轮数据、环境和验证结果：[performance-goal-20260912.json](performance-goal-20260912.json)。运行脚本：[run_c_rust_comparison.sh](run_c_rust_comparison.sh)。


默认每 5 秒读取一次 WebUI 快照，同时运行 100 QPS 15 秒：1500 个正确响应、0 错误/超时，P99 0.397 ms。最终快照包含 1000 条正确历史、256 条缓存，活动查询数为 0。
