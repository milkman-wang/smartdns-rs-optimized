# 家用低负载延迟与线程选择，2026-09-06

## 结论

不要把饱和负载下的 P99 当作家用查询延迟。当前优化版在 BE10000 上固定 100 QPS 时，缓存命中的中位耗时约 0.2 ms；1、2、4 个工作线程之间的差距只有十几微秒。没有证据支持为了低延迟，把发布版统一限制为 1 或 2 线程。

运行时未指定 `num-workers` 就使用 `std::thread::available_parallelism()`，获取失败才回退到 1。显式配置覆盖这一值。此前的 `num-workers 2` 只写入该路由器的自定义配置，没有改变全局默认值。自动识别 CPU 数保证适配性，不等于自动寻找性能最优值。

## 固定 100 QPS 的线程对照

使用同一已部署 SmartDNS-rs 二进制、256 个域名和 4,096 条缓存，关闭测试实例的持久化、预取、测速和双栈选优。独立网络命名空间内先预热，再暂停固定上游，确认计时期不需要回源。服务可使用全部四个核心，客户端固定在 CPU 0，保持原有 ondemand governor。

每组 3 轮，每轮 10 秒，固定目标 100 QPS，最多 4 个未完成请求；三轮按 `1/2/4`、`2/4/1`、`4/1/2` 线程顺序交替。下表是逐轮指标的中位数。

| 工作线程 | P50 | P95 | P99 | 服务 CPU，100%=一核 |
|---|---:|---:|---:|---:|
| 1 | 0.210 ms | 0.281 ms | 0.357 ms | 1.4% |
| 2 | 0.223 ms | 0.279 ms | 0.362 ms | 1.5% |
| 4 | 0.231 ms | 0.309 ms | 0.418 ms | 1.5% |

九轮均完成 1,000 个查询，零错误、零超时。单轮 P99 有波动：1 线程某轮达到 1.738 ms，4 线程某轮达到 1.297 ms。三轮不足以证明某个线程数的尾延迟必然最优。这里包含本机 socket、调度与客户端开销，不是纯函数耗时，也不是 Windows 客户端经过 LAN 的完整延迟。

## 首次公网查询的策略等待

正式配置写有 `response-mode fastest-ip`，但未配置 `speed-check-mode`。按当前 `dns_mw_ns.rs` 的实际分支，上游 A/AAAA 查询在没有测速模式时会使用 `fastest-response`，所以单改响应模式没有收益。双栈中间件仍独立进行 IPv4/IPv6 查询和可达性比较。

启动两个使用完整规则和原上游的测试实例，均为 2 线程、关闭本机缓存与预取，仅将 `dualstack-ip-selection` 分别设为开和关。Windows LAN 客户端对 6 个常见域名发送 A/AAAA 查询，3 轮交替，共 72 次，均正常返回。每个模式、记录类型有 18 个样本。

| 中位延迟 | 双栈选优开启 | 双栈选优关闭 |
|---|---:|---:|
| A | 39.99 ms | 38.73 ms |
| AAAA | 45.76 ms | 35.28 ms |

AAAA 查询中位数少约 10.5 ms。公网路由、上游缓存、返回地址和测量顺序都会影响数据；这不是固定加速比例。测试没有验证网页连接速度一定改善。

关闭双栈选优**不是禁用 IPv6**，仍可返回 AAAA；它取消解析器基于 IPv4/IPv6 比较而抑制某些答案的行为，更多依赖客户端选择可用连接。IPv6 质量不稳定时，这项取舍可能不合适，所以保留为用户可选配置，没有修改正式服务或发布版默认值。

## 后续优先级

发布版继续自动选择工作线程，并保留手动覆盖。通用低延迟优化应减少请求经过的任务和通道、响应复制及共享锁竞争，验证不同线程数都受益。负响应缓存和同域名并发请求合并也值得单独评估，以减少重复回源；本轮没有实现这些变化或声称已测得收益。

针对家用，应分别测量缓存命中、首次查询、过期刷新和短时突发，并观察前台延迟、后台 CPU 与答案语义。不能为了让 DNS 数字好看，直接取消用户需要的地址选择策略。

## 复现与产物

原始结果见 [latency-20260906.json](latency-20260906.json)。[router_dnsbench.rs](router_dnsbench.rs) 新增末尾可选参数 `QPS`，省略或设为 0 保持饱和模式；[run_router_latency.sh](run_router_latency.sh) 使用固定 100 QPS。

```sh
# 在主机交叉编译，上传产物为 dnsbench-paced。
cargo build --manifest-path contrib/perf/Cargo.toml --locked --release --target aarch64-unknown-linux-musl
cp contrib/perf/target/aarch64-unknown-linux-musl/release/router_dnsbench dnsbench-paced

# 在四核路由器上，先准备目录、脚本和待测 smartdns。
D=/tmp/smartdns-perf
N=smartdns-latency
ip netns add "$N"
ip netns exec "$N" ip link set lo up
ip netns exec "$N" taskset 1 "$D/dnsbench-paced" server 5301 &
echo $! > "$D/latency-upstream.pid"
ip netns exec "$N" env PERF_DIR="$D" sh "$D/run_router_latency.sh" \
  "$D/smartdns" 2 lowload-w2
kill "$(cat "$D/latency-upstream.pid")"
ip netns delete "$N"
```

基准 C 代码通过 `-Wall -Wextra` 编译，脚本通过 ShellCheck；9,000 次本机查询和 72 次公网比较通过。测试实例和命名空间已清理，正式二进制与配置没有修改。本轮只有测量工具和说明更新，没有新的 Rust 行为修改，也未重跑完整测试套件。
