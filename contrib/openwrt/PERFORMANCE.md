# SmartDNS-rs 在 OpenWrt 上的性能

2026-09-06 已在实际 QWRT / ipq95xx 四核路由器上完成 Rust 版本优化测试。相对已修复缓存后台查询的旧版，最终版本在相同 4 线程配置下，热缓存吞吐中位数由 **27,837 QPS 升至 43,277 QPS（+55%）**；该设备调整为 2 线程后达到 **55,081 QPS（+98%）**。

这是同一路由器上的 Rust 版本前后对照，使用独立网络命名空间、本地回环、256 个域名、32 个并发请求，每组 5 轮。它不代表公网解析延迟也降低相同比例，也没有与 C SmartDNS 做同条件比较。

完整配置、原始数据、复现工具和功能验证见 [路由器实测报告](../perf/router-20260906.md)。

后续已完成 [OxiDNS 1.5.2 同机对照](../perf/oxidns-20260906.md)：在双方均为 2 线程的简单热缓存负载下，OxiDNS 的吞吐高 47.2%。该报告还记录了未保留的缓存锁优化实验。

## 已落实的优化

- 有效缓存命中直接返回，避免每次命中都创建后台查询；过期缓存刷新与预取仍保留。
- 缓存插入在返回前完成，减少一次任务调度，也保证后续请求能立即使用缓存。
- 更新缓存时清除预取标记，允许该条目参与下一轮预取；同时最多预取 16 个域名、每秒最多启动一批，避免集中刷新造成内存峰值和前台延迟。
- 发布配置使用 `opt-level=3`，保留 LTO 和单 codegen unit。实测静态二进制由约 6.3 MB 增至 9.3 MB，换取更高吞吐。
- OpenWrt 包显式覆盖 `CARGO_PROFILE_RELEASE_OPT_LEVEL`。仅修改 Cargo.toml 不够：SDK 的 [rust-values.mk](https://github.com/openwrt/packages/blob/master/lang/rust/rust-values.mk) 会通过环境变量设置 `opt-level=z`。

## 如何选择配置

本次设备上 2 个工作线程优于 4 个，但没有把 Rust 的全局默认线程数改为 2。不同 CPU、上游协议和规则规模仍需实测。可在自定义配置中设置 `num-workers 2`，然后对照自己的业务负载。

性能测试至少分开热缓存、缓存未命中、静态规则和加密上游。统计吞吐、错误/超时、P95/P99、CPU 与实际 RSS。CPU 百分比需要结合吞吐看：饱和测试中 CPU 更高，可能只是完成了更多请求。

若要比较 Rust 与 C，应使用同一设备、等价配置、相同规则和上游，并交替测量两个实现。语言本身不能保证固定性能倍数。本次数据不能推导 Rust 比 C 快多少。
